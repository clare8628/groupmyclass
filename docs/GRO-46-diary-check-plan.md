# GRO-46 小日記漏寫檢查程式 — 規劃

## 目標
1. 每天檢查 Google Doc：前一天 Johnson / Julia 誰沒寫小日記 → Email 通知。
2. 每月底產出各人漏寫統計，每漏 1 次扣零用錢 100 元。

## 架構（沿用既有 Cloudflare Worker + Cron + D1，不新增服務）
- **獨立 Worker `diary-checker`**（不混入 groupmyclass 學生分組系統，避免耦合）。
- Cron Trigger：每日 08:00 台北（`0 0 * * *` UTC）檢查前一天；每月最後一天 21:00 台北另寄月報（Worker 內判斷「明天是 1 號」）。
- 讀取 Doc：Google Docs API `documents.get`（service account 唯讀），或文件開「知道連結者可檢視」後用 `/export?format=txt`（免金鑰，最簡單，但連結外洩即可讀）。
- 解析：依日期標題切段，段內找 `Johnson` / `Julia` 小標，內容去空白後為空（或僅範本字樣）即視為漏寫。
- 儲存：D1 表 `diary_log(date, person, written, checked_at)`，主鍵 (date, person)，重跑冪等；月報由此表聚合。
- Email：Cloudflare Email Service（send_email binding）或 Resend API 擇一。
- 通知：日報「僅在有人漏寫時寄」；月報每月必寄（含 0 次）。
- 金額：`漏寫次數 × 100`，每人分別列出日期明細與合計。

## 邊界處理
- 日期格式多樣（`10/26`、`2026-10-26`、`10月26日`）→ 容錯解析，解析不到時寄「格式異常」警示，不默默當作漏寫。
- 前一天整段日期標題不存在 → 視為兩人皆漏寫（需確認，見問題 5）。
- 補寫：每日重新檢查最近 N 天，補寫後更正 D1 紀錄，月報以月底最終狀態為準。
- 重複寄信：以 `diary_log.notified` 旗標防止。

## 需要您提供的資訊
1. **文件存取方式**：（a）改成「知道連結者可檢視」，或（b）把文件共用給我建立的 service account email（較安全）。請擇一。
2. **文件實際格式範例**：貼 2–3 天內容（含日期行、Johnson/Julia 標記的真實寫法、哪種算「沒寫」，例如留空、只有標題、範本字樣）。文件為多頁籤時，指明要檢查的 tab（目前網址 `tab=t.0`）。
3. **收件 Email**：通知寄給誰（一個或多個）、寄件網域（Cloudflare Email 需已驗證網域；若無則用 Resend + 其 API key）。
4. **時間**：日報幾點寄？時區是否台北？月報是月底當晚還是次月 1 日早上？
5. **規則細節**：
   - 前一天完全沒日期標題，算兩人皆漏寫嗎？
   - 週末／假日／旅行日是否免寫？有的話如何標記（或提供豁免日清單）？
   - 補寫後是否撤銷該次漏寫？截止期限（例如隔天中午前）？
   - 內容少於幾字算沒寫？
6. **起算日**：從哪天開始計算（避免歷史資料被誤算）。
7. **月報形式**：只寄 Email 即可，或也要試算表／後台頁面可查歷史？
8. **部署**：同意新建獨立 repo（或放在本 repo `workers/diary-checker/`）並走 GitHub → Cloudflare 自動部署。

## 實作步驟（確認資訊後）
1. 解析器 + 單元測試（用您提供的真實樣本）
2. D1 schema + 每日檢查 + Email
3. 月報聚合 + 扣款計算 + 測試
4. GitHub push → Cloudflare 自動部署，驗證一次試跑信
